# Design

## Context

本变更建立在核心 Agent 已具备问答、定位、补丁、记忆、权限与多 Agent 编排能力之上。约束如下：

- 单机 CLI、Python 3.11+，无服务端；所有治理逻辑必须在进程内完成。
- 索引与运行记录写在本地 `.pmagent/`，可能存在共享目录场景（单写者）。
- 模型与向量化依赖外部 API，需要限速与成本控制。
- 审计结果需要作为权限体系的证据，必须不可静默篡改。

## Goals / Non-Goals

**Goals:**

- 让工具在出问题时能自证：有自检、有进度、有可验证的审计。
- 让成本与并发可控：预估、限流、配额三者协同。
- 让资源占用有上限：回收策略明确且不误删近期数据。

**Non-Goals:**

- 不做服务端监控平台，只提供指标导出接口。
- 不做分布式配额（单机多用户范围）。
- 不实现索引制品分发的服务端存储。

## Decisions

### D1 令牌桶 + 并发闸门双层限流

**决策**：按供应商维度维护令牌桶，同时在子 Agent 维度设置并发上限；超额请求排队而非直接失败，排队超过截止时间才快速失败。

**理由**：多 Agent 并行扇出会在瞬间产生 4 倍请求量，只做并发上限会在长任务下持续打满；只做速率限制又会让短时突刺超限。两层配合才能既平滑又不过度保守。

**备选**：仅重试退避（已触发限流，代价已发生）；仅队列（延迟不可控）。

### D2 配额失败时放行并告警

**决策**：配额读取或计数失败时，放行请求并记录告警，而不是拒绝。

**理由**：计量属于辅助设施，不应因它自身故障阻断主业务；误放行的成本远小于全员不可用。真正需要严格阻断的是用户主动超额，那种情况配额读取是正常的。

### D3 审计用哈希链而非外部存储

**决策**：每条审计记录包含上一条记录的哈希，形成链；提供 `audit verify` 校验并定位断链。

**理由**：不引入额外服务与凭据管理，单文件即可验证；能发现静默篡改（断链），满足"审计可被信任"的最低要求。

**备选**：写入独立只追加存储（需要额外基础设施）；数字签名（密钥管理复杂，收益有限）。

### D4 回收采用双阈值

**决策**：同时按保留天数与目录容量判断，任一超限即清理最旧数据，但始终保留最近 N 天。

**理由**：单看时间会在高峰期撑爆磁盘，单看容量会在低频期误删刚产生的内容。双阈值兼顾两种失效模式。

### D5 灰度以指标对比为准，不做自动决策

**决策**：灰度分流后对比两组的准确率、成本与失败率，由人决定是否全量；系统只提供对比与一键回退。

**理由**：自动判断"新模型是否更好"需要统计显著性与业务判断，误判代价高；把决策权留给人，系统保证可观测与可回退。

## 模块设计

### M20 OpsGuard

**职责**：运行层治理：自检、进度、限流配额、审计完整性、回收、成本预估、灰度。

| 能力 | 关键设计 |
|---|---|
| 健康自检 | `pmagent doctor` 七项检查，逐项给出修复建议 |
| 进度事件 | 统一 `ProgressEvent{run_id, phase, agent_role, budget_used, elapsed_ms}`；文本进度条，JSON 逐行 |
| 限流 | 令牌桶（按供应商）+ 并发闸门（子 Agent ≤4），排队超时快速失败 |
| 配额 | 用户 × 日 / 月用量；超限退出码 5 并给出重置时间 |
| 审计 | 前一条哈希入记录；`audit verify` 定位断链位置 |
| 回收 | 时间与容量双阈值，保留窗口可配 |
| 成本预估 | 依据历史均值与输入规模估算，超阈值需 `--yes` |
| 灰度 | 按比例分流 + 指标对比 + 一键回退 |

**失败模式**：限流队列积压超过截止时间 → 快速失败并提示；配额读取失败 → 放行并告警；GC 失败 → 跳过并记录，不阻塞主流程；哈希链断裂 → 报告具体位置但仍允许使用，标注"审计不完整"。

## Risks / Trade-offs

| 风险 | 影响 | 缓解 |
|---|---|---|
| 配额误伤 | 计量故障导致正常请求被拒 | 读取失败即放行并告警；配额可临时豁免 |
| 灰度指标不可比 | 分流样本太小导致结论错误 | 设置最小样本量，不足时延长灰度 |
| 术语表维护成本 | 多语言输出与实际术语脱节 | 术语表版本化并纳入评审 |
| 自检耗时 | 每次执行都自检拖慢启动 | 自检只在显式命令与失败时运行 |

## Migration Plan

本变更作为核心变更之后的独立阶段实施：

| 阶段 | 交付 | 验收 |
|---|---|---|
| H1 治理基线 | 自检、进度事件、限流与配额 | doctor 覆盖七项；长任务进度可见；并发峰值不触发 429 |
| H2 可信与回收 | 审计哈希链、资源回收、成本预估 | 篡改可检出；磁盘不超阈值；预估与实际偏差 < 30% |
| H3 交付增强 | 批量、供应链、灰度、多语言 | 批量可用；SBOM 可产出；灰度可回退；中英文一致 |

**回滚**：每项能力可用配置开关关闭（`ops.doctor`、`ops.ratelimit` 等），关闭后行为退化为核心变更的实现。
