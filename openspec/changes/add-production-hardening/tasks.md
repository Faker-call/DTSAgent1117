# Tasks

## 实施前提

- 本变更依赖 `add-render-engine-qa-diagnosis-agent` 先行落地（复用其 CLI、审计、模型网关与索引模块）。
- 治理能力以配置开关隔离（`ops.doctor`、`ops.ratelimit`、`ops.quota`、`ops.gc` 等），默认开启、可单独关闭。
- 配额读取失败时放行并告警，不因计量故障阻断业务。

## 1. 健康自检与进度（H1）

- [ ] 1.1 实现 `ops/` 包与 `pmagent doctor`（配置、密钥、模型连通、索引完整性、锁状态、磁盘余量、沙箱可用），验证七项检查均输出结论与修复建议
- [ ] 1.2 实现 `ProgressEvent` 契约与进度事件总线，验证长任务执行中事件持续产出
- [ ] 1.3 实现进度渲染（文本进度条 + JSON 逐行 NDJSON），验证管道消费时事件逐行到达、结束输出最终对象

## 2. 限流与配额（H1）

- [ ] 2.1 实现按供应商的令牌桶与子 Agent 并发闸门（≤4），验证并发峰值不触发供应商限流
- [ ] 2.2 实现排队超时快速失败与提示，验证积压超过截止时间时返回明确错误而非静默等待
- [ ] 2.3 实现用户级日/月配额并与角色矩阵打通，验证超配额以退出码 5 结束并提示重置时间
- [ ] 2.4 实现配额计量故障时的放行与告警，验证读取失败不阻断主流程

## 3. 审计完整性与回收（H2）

- [ ] 3.1 实现审计哈希链（每条记录含前条哈希）与 `pmagent audit verify`，验证篡改单条记录可被检出并定位
- [ ] 3.2 实现资源回收（artifacts/traces/runs 双阈值 GC 与保留窗口），验证超阈值自动清理且不误删近期数据
- [ ] 3.3 实现 GC 失败跳过与记录，验证回收异常不影响主流程

## 4. 成本预估（H2）

- [ ] 4.1 实现 `--dry-run` 成本预估（依据历史均值与输入规模），验证预估与实际偏差 < 30%
- [ ] 4.2 实现超阈值确认门禁（`--yes`），验证未确认时只输出预估不执行

## 5. 交付增强（H3）

- [ ] 5.1 实现批量模式（`--batch <file>`，并发受全局闸门约束），验证单条失败不影响其余并输出汇总

- [ ] 5.3 实现模型/提示词灰度（按比例分流 + 指标对比 + 一键回退），验证灰度期间可回退且指标可比

## 6. 验收
