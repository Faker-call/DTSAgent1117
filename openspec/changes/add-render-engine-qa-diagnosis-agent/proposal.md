# Proposal

## Why

花瓣地图渲染引擎 SDK 的开发者支持目前高度依赖资深工程师的人工排查：一份问题工单往往需要同时阅读引擎日志、堆栈、渲染截图，再在百万行 C++ 代码与历史缺陷库之间反复比对，才能给出根因与修复方向。结果是定位周期长、结论不可复用、专家时间被同类问题反复消耗；随着 SDK 版本、渲染后端（GL/Vulkan）与平台分支持续分叉，人工比对成本还在线性上升。

因此需要一个智能 Agent，把"SDK 问答 → 现场证据解析 → 代码级定位 → 可评审的修复补丁"串成一条可追溯的闭环，并让每一次排查都沉淀为可评测、可复用的知识资产。

## What Changes

- 新增 Python CLI 形态的 Agent 工具 `pmagent`，支持单次命令与交互式会话；IDE 集成不在本期范围。
- 新增**代码索引与检索**能力：面向超大 C++ 引擎仓库做 AST 感知的符号索引、调用关系图与混合检索（BM25 + 向量 + 符号图扩展），支持基于 git 变更的增量更新。
- 新增**多源知识库**：摄取 SDK 文档/API 参考、示例代码、历史工单与缺陷记录，按 SDK 版本对齐，回答必须可溯源到具体文档或代码位置。
- 新增**证据接入层**：日志模板化与异常段提取、堆栈符号化（llvm-symbolizer / addr2line）、crash 转储解析、渲染截图/录屏的视觉分析、复现工程的沙箱编译与运行。
- 新增**问答**能力：意图路由（用法问答 / 缺陷排查 / 概念解释）、检索增强生成、引用溯源、证据不足时的主动澄清。
- 新增**故障定位**能力：症状 → 渲染管线阶段 → 候选符号 → 证据链评分，输出带置信度与反证的结构化定位报告（文件:行、符号、调用链、可疑提交）。
- 新增**修复建议**能力：在定位结论之上生成最小 diff、影响面分析与验证建议，产出为独立补丁工件供人工评审，**不自动修改或提交业务仓库**。
- 新增**编排与治理**能力：星型多 Agent 编排（中心派发、并行扇出、失败隔离、短路优先）、工具契约与三权分离、上下文预算管理、只读沙箱、脱敏与审计、成本上限。
- 新增**记忆与恢复**能力：L0–L3 四层记忆、证据账本与四级压缩瀑布、基于事件溯源的会话与运行中断恢复（恢复时复用缓存、不重复计费）。
- 新增**建议权与执行权分离**：模型只输出工具提案与结论草案，阶段工具白名单、参数裁决、执行与关键校验全部由代码完成，校验阶段结构上不可跳过。
- 新增**成功案例回流**：自动识别成功信号 → 候选案例 → 人工确认 → 复用到检索先验、few-shot 与评测种子，并支持失效标记与反例沉淀。
- 新增**身份与权限**：本地账号认证、四角色（管理员/维护者/开发者/观察者）与资源×动作权限矩阵，在命令入口与工具裁决两处执行，审计记录到人；索引构建与案例入库采用单写者锁。
- 新增**归属与审计字段**：记录运行者、主机与索引属主，为后续企业身份源接入预留扩展点。
- 新增**进度治理**：以产出增量（新增证据、代码位置、证据类别、候选收敛度）度量进度，识别停滞、振荡与循环并分级熔断，避免"工具调用热闹但任务不前进"。
- 新增**质量加固**：索引版本绑定与内容过滤、补丁应用可回滚、置信度校准、种子集扩充与标注一致性、回流案例留出集门禁、混沌与提示注入对抗回归。
- 新增**评测体系**：从历史工单构建种子用例集，度量检索命中、定位准确率、补丁可接受率与虚假置信度，并纳入离线回归。

明确不在本期范围（Out of Scope）：自动提交/合并补丁、替换人工 code review、对外提供 SaaS 化 API、非渲染引擎模块（如地图数据编译、导航算路）、移动端/桌面端 GUI。权限体系本期限定为本地账号、单机多用户、固定四角色；企业 SSO/LDAP 对接与多租户数据隔离不在本期（另立变更 `add-enterprise-sso`）。

## Capabilities

### New Capabilities

- `knowledge-indexing`: 代码与文档知识的统一摄取、增量索引与混合检索，是问答与定位的共同底座。
- `evidence-ingestion`: 日志、堆栈、crash、截图、复现代码等现场证据的解析、符号化与归一化，产出结构化问题上下文。
- `qa-dialog`: 面向开发者的 SDK 用法问答、概念解释与多轮澄清，回答附引用溯源。
- `fault-localization`: 从问题上下文推导根因假设，定位到代码符号与调用链，并输出可复核的定位报告。
- `patch-proposal`: 基于定位结论生成最小修复补丁、影响面分析与验证建议，作为待评审工件输出。
- `agent-orchestration`: 星型多 Agent 派发与汇总、并行扇出与去重、子 Agent 隔离与降级、工具契约与三权分离、上下文与成本治理、安全边界与审计。
- `session-memory`: 记忆分层留存、压缩后引用可回溯、会话与运行的中断恢复、长期记忆的人工确认写入。
- `case-feedback`: 成功信号识别、候选案例提取与去重、确认后的三路复用、失效降权与反例沉淀。
- `access-control`: 本地账号认证、四角色权限矩阵、命令与工具双点授权、审计归属、密钥隔离与单写者保护。
- `cli-interface`: 命令行入口、交互式会话、输出格式（文本/Markdown/JSON）与退出码约定。
- `evaluation`: 种子用例集、质量指标、离线评测与回归流程。

### Modified Capabilities

无。本仓库为新建 OpenSpec 根目录，尚无既有 capability。

## Impact

- **新增代码**：`DTSAgent` 仓库（Python 3.11+），分层为 CLI 层、身份与授权层、编排层、领域技能层、知识层、证据层、记忆层、模型网关层。
- **新增依赖**：`tree-sitter` + `tree-sitter-cpp`、`clang`/`llvm-symbolizer`、`sqlite-vec` 或 `faiss`、BM25（`rank_bm25` 或自建）、`jieba`（中文分词）、`typer` + `rich`、`pydantic`、`pytest`。模型接入：LLM 与视觉走 DeepSeek 公有云 API（`deepseek-flash`，密钥读环境变量 `DEEPSEEK_API_KEY`），embedding 走阿里云百炼（`qwen3.7-text-embedding`，密钥读环境变量 `QWEN3.7`）。
- **数据与合规**：用户日志与截图在出网前需脱敏（坐标、设备标识、令牌、路径）；代码 chunk 文本会随 embedding 发往百炼（已确认可接受，保留本地兜底开关）；补丁与报告落盘在 `artifacts/` 下，业务仓库保持只读。
- **运行环境**：索引构建与符号化以 Linux/macOS 为主（贴合引擎构建环境）；Windows 可运行 CLI，但符号化与沙箱编译能力降级。
- **外部系统**：首期以开源 `maplibre/maplibre-native` 替代真实引擎仓库、以合成 JSON 工单替代真实缺陷库；SDK 文档导出与 CI 编译校验按可用性接入，`--repo` 可切换回真实仓库。
- **配套变更**：运维治理（自检、进度、限流配额、审计链、回收、成本预估、批量、供应链、灰度、多语言）拆分为独立变更 `add-production-hardening`，需在本变更之后实施。
- **风险**：超大仓索引的构建时长与存储成本、LLM 幻觉导致错误定位、跨版本代码漂移使索引失效、多模态截图理解的准确率不足、替代语料与真实仓库存在结构差异。
