# Spec Delta

## Purpose

把模糊的渲染症状与零散证据收敛为可复核、可验证的代码级根因假设，避免凭经验猜测。

## ADDED Requirements

### Requirement: 症状到渲染管线阶段映射

系统 SHALL 将症状映射到渲染管线阶段，包括瓦片加载、矢量解码、几何三角化、纹理上传、着色器、绘制调用、相机变换、样式解析、标注布局与内存管理。

#### Scenario: 现象归类

- **WHEN** 输入描述"放大到 17 级后路网变细并出现断裂"
- **THEN** 系统给出对应管线阶段及归类依据，并列为后续候选检索的过滤条件

### Requirement: 候选生成

系统 SHALL 结合堆栈帧、混合检索结果、近期相关提交与历史相似工单生成候选符号集合，并标明每个候选的来源。

#### Scenario: 多来源候选

- **WHEN** 证据同时包含堆栈与相似历史工单
- **THEN** 系统合并两类来源的候选并逐一标注来源与初始权重

### Requirement: 证据链评分

系统 SHALL 为每个候选记录支持证据与反证，输出介于 0 与 1 之间的置信度及计算依据。

#### Scenario: 存在反证

- **WHEN** 某候选与日志中的时序或后端分支相互矛盾
- **THEN** 系统在报告中显式记录该反证并相应降低置信度

### Requirement: 高置信判定门槛

系统 MUST 仅在至少存在两类相互独立的证据时把结论标注为高置信，否则必须降级并说明缺失的证据类型。

#### Scenario: 单一证据

- **WHEN** 只有堆栈指向某函数而缺少日志、提交或工单佐证
- **THEN** 系统将该结论标注为中或低置信并列出需补充的证据类型

### Requirement: 结构化定位报告

系统 SHALL 输出包含症状、根因假设、代码位置、调用链、可疑提交、置信度、反证与下一步验证建议的定位报告。

#### Scenario: 生成定位报告

- **WHEN** 定位流程收敛到一个主要假设
- **THEN** 报告同时包含人类可读摘要与机器可解析结构，且两者结论一致

### Requirement: 定位结果可独立复核

系统 MUST 保证报告中每个代码位置都可被用户独立打开并与描述对应。

#### Scenario: 复核代码位置

- **WHEN** 用户按报告中的文件与行号打开代码
- **THEN** 该位置确实包含报告所述的逻辑，路径与行号未失效

### Requirement: 无法定位时的显式返回

系统 SHALL 在证据不足以支撑任何候选时返回无法定位，并列出使定位可行的最低补充材料。

#### Scenario: 证据不足

- **WHEN** 仅有一句主观描述且无任何可解析技术材料
- **THEN** 系统返回无法定位结论并给出所需材料清单，不输出猜测性根因
