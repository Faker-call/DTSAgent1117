# Spec Delta

## Purpose

在已确认的定位结论之上产出可评审、可验证、默认不落地的修复补丁建议，把排查结果转化为工程动作。

## ADDED Requirements

### Requirement: 补丁生成

系统 SHALL 基于定位报告与相关代码上下文生成最小 unified diff，并对每处改动给出理由。

#### Scenario: 生成单点修复

- **WHEN** 定位报告指向一个空指针未判空的分支
- **THEN** 系统产出的 diff 只修改该分支相关逻辑并逐处说明改动依据

### Requirement: 编码规范与兼容约束

系统 SHALL 遵守仓库既有编码规范，并避免破坏 ABI、线程模型或公共接口语义；确有必要时必须显式说明影响。

#### Scenario: 涉及公共头文件

- **WHEN** 修复需要修改对外暴露的头文件
- **THEN** 系统在说明中标注兼容性影响并给出替代方案

### Requirement: 补丁静态校验

系统 SHALL 对补丁执行格式检查与受影响编译单元的编译校验，并如实报告失败原因。

#### Scenario: 编译不通过

- **WHEN** 补丁导致受影响编译单元编译失败
- **THEN** 系统报告失败输出与定位并撤回该补丁，不将其作为有效建议呈现

### Requirement: 影响面分析

系统 SHALL 分析补丁的调用方、渲染后端差异、性能与回归风险。

#### Scenario: 多后端差异

- **WHEN** 修改位于共享的几何处理路径
- **THEN** 系统分别说明对 OpenGL 与 Vulkan 后端的影响及需要额外验证的场景

### Requirement: 不自动修改业务仓库

系统 MUST NOT 修改、暂存或提交业务仓库中的文件；补丁仅作为工件写入专用输出目录，需人工确认后才可应用。

#### Scenario: 默认不落地

- **WHEN** 补丁生成完成
- **THEN** 业务仓库工作区保持未修改状态，补丁以独立文件形式存在

#### Scenario: 人工应用

- **WHEN** 评审者明确要求将补丁应用到工作区
- **THEN** 系统执行应用并报告应用结果，冲突时保持仓库原状

### Requirement: 验证建议

系统 SHALL 输出复现步骤、建议新增或更新的测试用例以及验收标准。

#### Scenario: 给出验收标准

- **WHEN** 补丁针对瓦片缝隙问题
- **THEN** 系统给出可观察的验收判据，例如指定缩放级别下缝隙消失且帧耗时无明显回退

### Requirement: 补丁可回滚

系统 SHALL 在应用补丁前记录工作区快照，并提供回滚命令恢复到应用前状态。

#### Scenario: 应用后编译失败

- **WHEN** 补丁应用后受影响编译单元编译失败
- **THEN** 用户可用一条命令回滚到应用前状态，仓库内容与快照一致
