# Spec Delta

## Purpose

把异构的现场材料（日志、堆栈、崩溃转储、渲染截图、复现代码）转换为 Agent 可推理、可追溯的结构化问题上下文。

## ADDED Requirements

### Requirement: 证据归一化

系统 SHALL 将日志、堆栈、崩溃转储、截图与复现代码归一化为统一的问题上下文对象，并保留每项证据的原始出处。

#### Scenario: 混合证据输入

- **WHEN** 用户同时提供日志、截图与复现代码
- **THEN** 系统生成单一问题上下文，且其中每个字段都能追溯到原始文件与位置

### Requirement: 日志模板化与异常提取

系统 SHALL 对日志做模板抽取与异常聚类，识别错误码、关键时间线与重复模式，同时保留原始行以便复核。

#### Scenario: 提取异常段

- **WHEN** 输入包含数十万行的引擎日志
- **THEN** 系统输出压缩后的错误模板、首次与末次出现位置及对应原始行号

### Requirement: 堆栈符号化

系统 SHALL 在提供符号或调试信息时把地址解析为函数、文件与行号；无法解析时保留原始帧并说明降级原因。

#### Scenario: 成功符号化

- **WHEN** 提供带调试信息的引擎二进制与堆栈地址
- **THEN** 系统输出带函数名、文件与行号的解析帧

#### Scenario: 缺少符号信息

- **WHEN** 堆栈来自 release 包且无对应符号表
- **THEN** 系统保留原始地址帧并标注无法符号化的具体原因

### Requirement: 视觉证据分析

系统 SHALL 从截图或录屏中提取可判读的渲染异常特征，例如残影、瓦片缝隙、错位、色差与闪烁，并标出对应区域。

#### Scenario: 截图异常识别

- **WHEN** 用户上传一张疑似渲染异常的截图
- **THEN** 系统输出异常类型、置信度与异常区域描述，供后续推理引用

#### Scenario: 截图信息不足

- **WHEN** 截图无法判读或分辨率过低
- **THEN** 系统明确说明无法从图像得出结论并请求补充材料

### Requirement: 复现工程沙箱运行

系统 SHALL 在隔离沙箱中编译并运行复现代码，采集日志与退出状态，且受超时与资源上限约束。

#### Scenario: 沙箱运行成功

- **WHEN** 提供可编译的复现工程
- **THEN** 系统返回构建结果、运行日志与关键指标，并标注沙箱环境差异

#### Scenario: 沙箱资源超限

- **WHEN** 复现运行超过配置的时长或资源上限
- **THEN** 系统终止运行并报告超限原因，不视为定位失败

### Requirement: 证据充分性判定

系统 SHALL 评估现有证据是否足以支撑问答或定位，证据不足时输出具体的补充材料清单。

#### Scenario: 证据不足

- **WHEN** 只有一句模糊的现象描述而无版本、日志或复现路径
- **THEN** 系统列出需要补充的最少证据项，并说明各项用于排除什么假设

### Requirement: 敏感信息脱敏

系统 MUST 在证据离开本地或落盘前对坐标、设备标识、令牌与个人路径等敏感信息脱敏。

#### Scenario: 日志出网

- **WHEN** 证据需要发送至外部模型服务
- **THEN** 系统先完成脱敏并保证脱敏后的文本仍保留排障所需语义，映射关系仅保存在本地
