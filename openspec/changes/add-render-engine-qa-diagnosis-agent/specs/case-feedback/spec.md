# Spec Delta

## Purpose

把被验证成功的排查过程自动沉淀为可复用案例，在人工确认后反哺检索、示例与评测，并淘汰失效案例、沉淀被拒反例。

## ADDED Requirements

### Requirement: 成功信号识别

系统 SHALL 识别补丁合入、工单关闭、复现消失与人工确认四类成功信号，并据此生成候选而非直接写入长期记忆。

#### Scenario: 补丁合入信号

- **WHEN** 补丁被应用后的提交信息携带该补丁的标识
- **THEN** 系统生成一条高可靠度的成功信号并关联到对应运行

#### Scenario: 复现消失信号

- **WHEN** 沙箱中复现现象消失但未获得人工确认
- **THEN** 系统生成中可靠度信号，并把对应候选标记为待复核

### Requirement: 候选提取与去重

系统 SHALL 从运行记录提取问题、证据、根因、修复与验证方法五元组生成候选案例，并按症状与根因位置指纹去重。

#### Scenario: 重复案例合并

- **WHEN** 两条信号指向同一根因位置与同一症状
- **THEN** 系统合并为一条候选并累加信号来源，不产生两条记录

### Requirement: 人工确认后入库

系统 MUST 仅在人工确认后把候选写入长期记忆，并记录适用版本与失效时间。

#### Scenario: 未确认候选

- **WHEN** 候选只有自动信号而无人工确认
- **THEN** 该候选不参与检索排序与示例池

### Requirement: 案例三路复用

系统 SHALL 将已确认案例复用于检索先验、示例池与评测种子，且复用不得改变证据类别。

#### Scenario: 检索先验生效

- **WHEN** 新问题与已确认案例症状相似
- **THEN** 系统提高该案例涉及文件与符号的候选权重，但报告中证据仍来自可核验来源

#### Scenario: 进入示例池

- **WHEN** 案例经脱敏并被选为示例
- **THEN** 对应阶段在生成时引用该示例，且每阶段示例数量受限

### Requirement: 失效与降权

系统 SHALL 在代码版本漂移或同类问题复发时标记案例过期或降低其权重。

#### Scenario: 行号漂移

- **WHEN** 案例引用的代码位置在当前版本已不存在
- **THEN** 系统把该案例标记为过期并停止参与排序

#### Scenario: 问题复发

- **WHEN** 已确认案例对应的问题在后续版本再次出现
- **THEN** 系统降低该案例权重并记录复发次数

### Requirement: 反例沉淀

系统 SHALL 把被拒绝的补丁沉淀为反例，供后续同类场景规避。

#### Scenario: 补丁被拒

- **WHEN** 评审者拒绝一条补丁并说明原因
- **THEN** 系统记录该反例及原因，后续补丁生成时作为规避项提示
