# Spec Delta

## Purpose

让 Agent 在长链路排查中保持上下文连续性，在进程中断后无重复计费地继续，并保证压缩后的结论仍可回溯到原始证据。

## ADDED Requirements

### Requirement: 记忆分层与留存

系统 SHALL 按工作记忆、会话记忆、任务记忆、长期记忆四层管理状态：工作记忆仅存在于进程内，会话记忆与任务记忆落盘可恢复，长期记忆跨会话保留。

#### Scenario: 会话记忆落盘

- **WHEN** 用户在一次会话中提供了 SDK 版本与平台
- **THEN** 这些信息写入会话记忆，新进程以同一会话标识打开时仍然存在

#### Scenario: 工作记忆不落盘

- **WHEN** 某个阶段结束
- **THEN** 该阶段的临时结构被释放，不写入持久化存储

### Requirement: 压缩后引用可回溯

系统 SHALL 在压缩上下文时保留每条结论到原始证据的引用标识，压缩后仍能定位回原文位置。

#### Scenario: 压缩前后引用一致

- **WHEN** 上下文中的代码片段被替换为位置摘要
- **THEN** 依据该引用仍能取回原文并校验行号有效

### Requirement: 压缩质量校验

系统 SHALL 在压缩后校验关键事实覆盖率，覆盖率不足时回退到上一级压缩方式。

#### Scenario: 事实丢失回退

- **WHEN** 压缩后的摘要遗漏了高权重事实，例如错误码或关键符号
- **THEN** 系统回退到较弱压缩并重新校验，而非继续推进

### Requirement: 会话跨进程恢复

系统 SHALL 支持以会话标识重新进入既有会话，恢复槽位、已排除假设与轮次摘要。

#### Scenario: 换终端续接

- **WHEN** 用户在新进程以同一会话标识继续提问
- **THEN** 系统不再重复询问已知的版本与平台，并沿用已排除假设

### Requirement: 运行中断恢复

系统 SHALL 以追加事件的方式记录运行过程，并支持从中断处继续，已完成阶段不重新执行。

#### Scenario: 中途中断后续跑

- **WHEN** 诊断在假设生成阶段被中断，用户随后请求继续
- **THEN** 系统复用已完成的证据解析与候选生成结果，从假设生成阶段继续

### Requirement: 恢复时不重复计费

系统 SHALL 缓存工具调用与模型调用结果，恢复运行时优先复用缓存结果。

#### Scenario: 恢复复用模型输出

- **WHEN** 恢复运行时某阶段的模型调用已有缓存
- **THEN** 系统直接复用该输出，不再发起新的模型请求

### Requirement: 恢复前校验版本一致性

系统 SHALL 在恢复前校验索引版本，版本不一致时显式提示并等待用户确认。

#### Scenario: 索引已更新

- **WHEN** 恢复的运行所用索引版本与当前索引不一致
- **THEN** 系统提示历史结论可能失效，并给出继续或指定阶段重跑两个选项

### Requirement: 长期记忆需人工确认写入

系统 SHALL 只在人工确认后把已解决案例写入长期记忆，并记录适用版本与失效时间。

#### Scenario: 人工确认后沉淀

- **WHEN** 评审者确认某条定位结论与修复正确
- **THEN** 该案例以问题、根因、修复三要素写入长期记忆，并带上版本标签与失效时间

### Requirement: 长期记忆不作为独立证据

系统 MUST 只用长期记忆提供检索先验，不得将其作为定位结论的证据类别。

#### Scenario: 相似案例命中

- **WHEN** 检索命中一条历史案例
- **THEN** 它只影响相关代码的候选排序，报告中的证据仍需来自代码、日志、堆栈等可核验来源
