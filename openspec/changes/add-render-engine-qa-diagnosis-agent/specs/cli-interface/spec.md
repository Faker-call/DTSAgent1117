# Spec Delta

## Purpose

为开发者提供可日常使用的命令行入口，使问答、定位与补丁评审能够嵌入现有排查流程和 CI。

## ADDED Requirements

### Requirement: 命令集

系统 SHALL 提供索引管理、问答、诊断、补丁、评测与配置六类子命令，并通过帮助信息说明各自用途。

#### Scenario: 列出可用命令

- **WHEN** 用户执行帮助命令
- **THEN** 系统列出子命令、作用与典型用法示例

### Requirement: 交互与单次两种模式

系统 SHALL 同时支持交互式多轮会话与一次性执行模式，且两者共享同一能力集合。

#### Scenario: 交互式追问

- **WHEN** 用户以交互模式启动并连续追问
- **THEN** 系统保留会话上下文并在退出时给出本次结论摘要

#### Scenario: 单次执行

- **WHEN** 用户在 CI 中以单条命令提交诊断输入
- **THEN** 系统完成诊断、按指定格式输出结果并以约定退出码结束

### Requirement: 输出格式

系统 SHALL 支持文本、Markdown 与 JSON 三种输出，其中 JSON 结构稳定并包含结论、证据与置信度字段。

#### Scenario: JSON 消费

- **WHEN** 用户指定 JSON 输出
- **THEN** 输出可被脚本解析，且字段名与结构在版本间保持兼容或明确标注破坏性变更

### Requirement: 退出码约定

系统 SHALL 用不同退出码区分成功、证据不足、定位失败与内部错误。

#### Scenario: 证据不足

- **WHEN** 诊断因证据不足而无法给出结论
- **THEN** 返回表示证据不足的专属退出码，而非与内部错误混用

### Requirement: 配置管理

系统 SHALL 通过配置文件与环境变量管理模型端点、索引位置、脱敏策略与预算上限，并支持初始化配置。

#### Scenario: 首次配置

- **WHEN** 用户在未配置环境中首次运行
- **THEN** 系统提示生成默认配置并说明必填项

### Requirement: 默认输出可解释

系统 SHALL 在默认输出中展示关键来源与置信度，而不只呈现最终结论。

#### Scenario: 查看来源

- **WHEN** 用户以默认文本模式查看定位结果
- **THEN** 输出包含代码位置、证据摘要与置信度，无需额外参数
