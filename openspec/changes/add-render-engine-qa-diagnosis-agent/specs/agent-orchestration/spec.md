# Spec Delta

## Purpose

定义 Agent 的工具契约、阶段编排与治理边界，使整条问答与定位链路可控、可审计、成本可预期。

## ADDED Requirements

### Requirement: 工具契约

系统 SHALL 以带参数与返回值 schema 的注册式工具暴露检索、符号化、沙箱运行、补丁校验等能力，并在调用前后做结构化校验。

#### Scenario: 非法参数

- **WHEN** 某次工具调用缺少必填参数
- **THEN** 系统拒绝该调用并返回可读的参数错误，不继续以残缺输入执行

### Requirement: 阶段化编排

系统 SHALL 按路由、检索、推理、校验、产出的阶段推进，每个阶段具备重试上限与终止条件。

#### Scenario: 阶段重试上限

- **WHEN** 某阶段连续失败达到配置上限
- **THEN** 系统终止该阶段并输出已完成部分与失败原因

### Requirement: 自主性边界

系统 MUST 默认以只读方式访问业务仓库与外部系统，写操作仅限专用输出目录且需显式开启。

#### Scenario: 未授权的写操作

- **WHEN** 流程试图写入业务仓库路径
- **THEN** 系统拒绝写入并记录该尝试

### Requirement: 上下文预算管理

系统 SHALL 在给定上下文体量内压缩或裁剪材料，保留证据引用；超预算时降级处理而非静默丢弃关键证据。

#### Scenario: 超出预算

- **WHEN** 检索结果与证据总量超过窗口预算
- **THEN** 系统优先保留与假设相关性最高的证据并标注被裁剪的内容范围

### Requirement: 运行审计

系统 SHALL 记录每次运行的模型标识、提示摘要、工具调用序列、token 消耗与耗时，并支持导出。

#### Scenario: 导出运行记录

- **WHEN** 用户需要复盘某次定位过程
- **THEN** 可导出包含完整工具调用链与耗时的运行记录

### Requirement: 成本与时长上限

系统 SHALL 支持会话级 token、费用与时长上限，达到上限时优雅终止并返回已完成结论。

#### Scenario: 触及成本上限

- **WHEN** 单次诊断消耗达到配置上限
- **THEN** 系统停止继续调用模型并输出当前已确认的结论与未完成步骤

### Requirement: 依赖不可用时的降级

系统 SHALL 在模型服务或外部工具不可用时降级到确定性流程，并明确告知用户当前能力受限。

#### Scenario: 模型服务超时

- **WHEN** 模型接口持续超时
- **THEN** 系统改用纯检索与规则流程输出可用信息，并标注未经过模型推理

### Requirement: 建议权与执行权分离

系统 SHALL 只接受模型输出的结构化工具提案，所有副作用由系统代码裁决后经统一执行器执行，模型不得直接产生副作用。

#### Scenario: 模型提议写文件

- **WHEN** 模型输出指向业务仓库路径的写入提案
- **THEN** 系统拒绝该提案并记录拒绝原因，仓库保持未修改

#### Scenario: 正常提案执行

- **WHEN** 模型提议调用当前阶段允许的检索工具
- **THEN** 系统校验参数后由统一执行器执行，并记录执行前后两条审计事件

### Requirement: 阶段工具白名单

系统 SHALL 为每个阶段定义允许调用的工具集合，并拒绝集合之外的提案。

#### Scenario: 跨阶段工具

- **WHEN** 在假设生成阶段提议调用沙箱运行工具
- **THEN** 系统拒绝该提案并返回该阶段可用的工具列表

### Requirement: 关键校验不可跳过

系统 MUST 把引用校验、报告自洽性检查与补丁编译校验作为固定流水线阶段，且不得将其暴露为模型可调用的工具。

#### Scenario: 模型试图省略校验

- **WHEN** 模型表达"跳过校验直接产出"的意图
- **THEN** 系统仍执行全部校验阶段，未通过则不产出结论

### Requirement: 命令来源受限

系统 SHALL 只执行复现工程配置或预置模板中声明的命令，不接受模型生成的任意命令。

#### Scenario: 模型生成命令

- **WHEN** 模型提议执行一条不在配置或模板中的命令
- **THEN** 系统拒绝并列出当前可用命令

### Requirement: 结论与置信度由代码判定

系统 MUST 由代码依据证据类别数、反证强度与阈值计算置信度，模型只能提交证据与反证，不得自填置信度。

#### Scenario: 模型自填高置信

- **WHEN** 模型输出包含置信度字段但证据类别数不足门槛
- **THEN** 系统忽略该字段，按代码规则给出降级后的置信度并说明缺口

### Requirement: 进度以产出增量度量

系统 SHALL 以新增证据、新增代码位置、新增证据类别与候选收敛度度量阶段进度，而非以工具调用次数度量。

#### Scenario: 调用多但无产出

- **WHEN** 某阶段连续多次工具调用均未带来新的证据或代码位置
- **THEN** 系统判定该阶段为停滞，并在进度记录中标注调用数与新增证据数

### Requirement: 停滞熔断

系统 SHALL 在判定停滞时执行分级处置：首次要求更换检索通道或切片范围，第二次强制收敛为产出结论与缺口说明。

#### Scenario: 连续空调用

- **WHEN** 连续四次调用未产生任何新增证据
- **THEN** 系统禁止继续探索，只允许组装已得结论并说明缺失项

### Requirement: 振荡与循环抑制

系统 SHALL 识别假设集合高频重合的振荡与同参数重复调用的循环，并拒绝重复提案。

#### Scenario: 反复自我否定

- **WHEN** 连续两轮假设集合高度重合且没有新增证据
- **THEN** 系统判定为振荡并停止该阶段的假设生成

#### Scenario: 重复调用

- **WHEN** 同一工具以相同参数再次被提议
- **THEN** 系统拒绝该提案并记为无效调用

### Requirement: 硬性资源上限

系统 SHALL 为每阶段调用次数、单次运行总调用次数与墙钟时间设置硬上限，超限时以降级状态收尾。

#### Scenario: 触及调用上限

- **WHEN** 单次运行的工具调用总数达到上限
- **THEN** 系统停止调用并以已获得的信息产出降级结论

### Requirement: 进度可观测

系统 SHALL 在运行详情与最终报告中展示每阶段的调用数、新增证据数与停滞判定结果。

#### Scenario: 查看运行进度

- **WHEN** 用户查看某次运行的详情
- **THEN** 可以看到每个阶段的进度快照与是否发生过停滞

### Requirement: 星型多 Agent 编排

系统 SHALL 由中心编排者向领域子 Agent 派发任务并汇总结果，子 Agent 之间不得直接通信。

#### Scenario: 子 Agent 尝试互调

- **WHEN** 某个子 Agent 试图直接调用另一个子 Agent
- **THEN** 系统拒绝该调用，要求经中心编排者派发

### Requirement: 派发与短路

系统 SHALL 在证据充分且意图为用法类时走单 Agent 路径，仅在需要多源证据或定位推理时启动多 Agent。

#### Scenario: 简单用法问题

- **WHEN** 用户询问某个接口如何调用且证据充分
- **THEN** 系统直接由知识问答子 Agent 回答，不启动多 Agent

### Requirement: 并行扇出与去重汇合

系统 SHALL 支持由中心编排者并发发起多个检索分支，并在汇合时按证据指纹去重。

#### Scenario: 多源并行检索

- **WHEN** 定位流程需要同时检索代码、文档、工单与历史案例
- **THEN** 系统并发执行四个分支，汇合后去除重复证据再交给定位子 Agent

### Requirement: 子 Agent 隔离与失败降级

系统 SHALL 为每个子 Agent 施加独立的工具白名单、预算与截止时间，单个分支失败不得阻塞整体。

#### Scenario: 分支超时

- **WHEN** 某个检索分支超过截止时间
- **THEN** 系统终止该分支，其余分支正常汇合，并在结果中标注该分支缺口

### Requirement: 汇总冲突裁决

系统 SHALL 在汇总阶段按置信度与证据强度裁决冲突结论，无法裁决时交由独立评审者复核。

#### Scenario: 同一位置相反结论

- **WHEN** 两个分支对同一代码位置给出相反判断
- **THEN** 系统保留置信度高者并记录反证；若差距不足阈值则标记待复核

### Requirement: 子 Agent 贡献度可归因

系统 SHALL 记录每个子 Agent 的调用数、证据贡献与耗时，以支持成本归因与效果评估。

#### Scenario: 事后归因

- **WHEN** 需要分析某次诊断的成本构成
- **THEN** 可以按子 Agent 看到各自的 token 消耗与贡献的证据数量
