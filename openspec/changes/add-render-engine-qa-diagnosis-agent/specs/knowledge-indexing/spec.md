# Spec Delta

## Purpose

为问答与故障定位提供统一、可增量更新、可溯源的代码与文档检索底座，使系统在超大 C++ 引擎仓库中仍能快速收敛到相关符号与权威资料。

## ADDED Requirements

### Requirement: 代码符号索引

系统 SHALL 从引擎仓库构建 AST 级符号索引，覆盖文件、命名空间、类、函数、宏与 include 依赖，并为每个符号记录签名、定义位置与所属编译单元。

#### Scenario: 建立全量索引

- **WHEN** 用户对引擎仓库执行全量索引构建
- **THEN** 系统产出包含符号、位置与依赖关系的索引，并报告被索引文件数与耗时

#### Scenario: 按符号检索

- **WHEN** 用户或内部流程以符号名查询索引
- **THEN** 系统返回匹配符号的完整签名、文件路径与定义行号

### Requirement: 混合检索

系统 SHALL 支持关键词检索、向量语义检索与符号图扩展的组合检索，返回排序后的候选并标明每个候选的命中通道与原因。

#### Scenario: 组合检索命中

- **WHEN** 以自然语言描述一个渲染现象发起检索
- **THEN** 系统返回合并排序结果，且每条结果标注来自关键词、向量或符号图扩展中的哪些通道

#### Scenario: 无相关结果

- **WHEN** 检索在阈值内没有可信命中
- **THEN** 系统返回空结果集并显式声明未命中，而非填充低相关内容

### Requirement: 增量更新

系统 SHALL 基于 git 提交差异只重建受影响文件及其直接依赖，并在更新失败时保留上一次可用索引。

#### Scenario: 提交后增量更新

- **WHEN** 引擎仓库出现新提交
- **THEN** 系统仅重建受影响范围并在完成后更新索引版本标识

#### Scenario: 更新中断

- **WHEN** 增量更新过程中发生中断或错误
- **THEN** 系统回滚到更新前状态并保持查询可用

### Requirement: 文档与缺陷知识摄取

系统 SHALL 摄取 SDK 文档、API 参考、示例代码、历史工单与缺陷记录，并为每条知识保留来源、适用版本与更新时间。

#### Scenario: 摄取多源资料

- **WHEN** 导入一批文档与工单
- **THEN** 每条记录都带有可回到原始出处的标识与版本元数据

### Requirement: 版本对齐

系统 SHALL 按 SDK 版本或引擎 commit 区分知识版本，并默认将检索限定在问题声明的版本范围内。

#### Scenario: 版本已知

- **WHEN** 问题中声明了 SDK 版本或引擎 commit
- **THEN** 检索结果仅来自该版本及明确标注为跨版本的资料

#### Scenario: 版本缺失

- **WHEN** 问题未提供版本信息
- **THEN** 系统提示需要补充版本，或明确标注结果可能跨版本不适用

### Requirement: 检索结果可溯源

系统 MUST 为每条检索结果携带可独立验证的来源标识，例如文件路径与行号、文档 URL 或工单编号。

#### Scenario: 校验结果来源

- **WHEN** 用户要求查看某条结论的来源
- **THEN** 系统给出可打开验证的具体位置或链接，且该位置真实存在

### Requirement: 索引制品分发

系统 SHALL 支持把索引打包为制品并分发，拉取后校验完整性再使用。

#### Scenario: 从制品恢复索引

- **WHEN** 用户从共享位置拉取索引制品
- **THEN** 系统校验校验和并直接可用，无需在本地重新全量构建

### Requirement: 索引版本绑定

系统 MUST 在索引清单中记录切块策略版本、向量化模型标识与维度、索引结构版本，任一与运行时不一致时拒绝查询。

#### Scenario: 更换向量化模型

- **WHEN** 当前向量化模型与索引记录的模型不一致
- **THEN** 系统拒绝检索并提示重建，而不是返回可能错误的结果

### Requirement: 索引内容过滤

系统 SHALL 默认排除第三方依赖、生成代码与 vendor 目录，并允许扩展排除规则。

#### Scenario: 仓库包含第三方目录

- **WHEN** 仓库中存在第三方依赖目录
- **THEN** 这些文件不进入索引，构建报告给出被排除的数量
