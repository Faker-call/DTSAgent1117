# 定位基线

## 设置

- 索引：`corpus/.index`（maplibre-native，2,228 文件 / 17,450 切块）
- 用例：`data/tickets/synthetic_tickets.json`，64 条
- 流程：`EvidenceNormalizer` → `DiagnosisAgent`（确定性假设生成，无模型）
- 证据：仅工单症状文本，无堆栈/日志

## 结果

| 指标 | 数值 |
|---|---|
| Top-1 文件命中 | **0.000** |
| Top-3 文件命中 | **0.000** |
| 虚假高置信率 | **0.000** |
| 单次中位耗时 | 444 ms |

## 分析

1. **命中为 0 的原因与检索基线一致**：症状是中文、代码是英文标识符，当前无向量通道，无法跨语言匹配；候选只能来自 BM25 与符号图，命中不到根因文件。
2. **虚假高置信率为 0 是正面结果**：高置信门槛（≥2 类证据、无强反证、≥0.75）确实拦住了"只靠单一证据就下高置信结论"。即便全错，也没有误报高置信。
3. **耗时 444 ms** 说明确定性链路本身很轻，瓶颈在检索质量而不是计算。

## 下一步

- 向量化语料后重跑：预计 Top-3 会显著改善，届时建立真实基线。
- 用真实工单替代合成语料：合成工单的根因文件是虚构路径，部分在语料中不存在，本身就会压低命中率。
- 本基线应视为**下界**，不用于判断定位架构优劣。
