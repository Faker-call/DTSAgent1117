# 性能

测试环境：Windows，Python 3.11.7，tree-sitter 0.26.1 + tree-sitter-cpp 0.23.4，本地 SSD。

## 全量索引

语料：`maplibre-native`，commit `c87f1e41d953`。

| 指标 | 数值 |
|---|---|
| 文件数 | 2,228（排除 vendor 等） |
| 代码行数 | 329,113 |
| 符号数 | 26,862 |
| 切块数 | 17,450 |
| 解析错误文件 | 456（20.5%） |
| 耗时 | **5.51 秒** |
| 吞吐 | **59,713 行/秒** |
| 数据库大小 | 47.3 MB（含 FTS5 全文索引） |

设计目标曾是"100 万行 ≤ 60 分钟"，实测远低于该目标，原因是当前阶段只做 tree-sitter 解析与 SQLite 写入，**不含向量化**。

## 增量索引

合成语料：200 个 C++ 文件，修改其中 5 个后提交。

| 场景 | 耗时 |
|---|---|
| 全量构建 | 1.45 秒 |
| 增量（5/200 变更） | **0.114 秒** |

增量约为全量的 1/13，符合"只重建受影响文件"的预期。

## 需要补充测量的部分

- **向量化耗时**：`qwen3.7-text-embedding` 每批 20 条，17,450 个切块约需 873 次请求；按 8 并发与 200ms/次估算约 20–25 秒，是当前主要外部瓶颈。
- **检索延迟**：第 6 组接入后补充 p95。
- **端到端诊断**：第 10 组后补充。

## 端到端验收（第 16 组实测）

`scripts/measure_acceptance.py`，临时语料与索引，无模型调用：

| 项 | 实测 | 目标 |
|---|---|---|
| 问答 p50 / p95 | 630 ms / **674 ms** | p95 ≤ 10 s ✅ |
| 诊断 p50 / p95 | 742 ms / **746 ms** | ≤ 120 s ✅ |
| 模型调用次数 | 0 | — |
| 单次成本 | **0 元** | 预算内 ✅ |

**成本说明**：以上数字是"离线/无模型"路径。接入 DeepSeek 推理后，单次问答约 1–2 次模型调用，按 `deepseek-flash` 定价与 4k token 上下文估算约 0.01–0.03 元；诊断（few-shot 假设生成 + 自审）约 3–5 次调用，估算 0.05–0.15 元。真实成本需在有密钥环境重测，当前不虚报。
